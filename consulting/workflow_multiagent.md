## 3. 지시서 표준형

Gemini에게 주는 모든 과제는 아래 6개 항목을 갖춘다. 하나라도 빠지면 산출물이 부정확해진다.

```
[과제 ID]      G-n
[목표]         한 문장. 과제는 한 번에 하나만.
[대상]         파일 경로 또는 DB명. 범위를 쪽수·연도로 한정.
[산출 형식]    표/목록 형식을 지정. 자유 서술 금지.
[종료 조건]    시간 상한 또는 범위 상한. 초과 시 중간 결과 보고.
[금지사항]     이미 확인된 내용 재요약 금지 / 근거 없는 문장 금지 등
```

### 공통 규칙 (모든 과제에 첨부)

```
1. 근거 없는 문장을 쓰지 마라. 모든 항목에 [확인] 또는 [미확인]을 붙여라.
2. [확인]에는 근거를 첨부하라 — 쪽수, URL, 관리번호, 고시번호, 청구기호 중 하나 이상.
3. 쪽수 없는 빈도 집계("N회 출현")는 무효다. 출현 쪽수와 앞뒤 문장을 함께 적어라.
4. 수치는 원문 표를 그대로 옮기고 합계를 재계산해 검산하라.
   직접 계산한 비율은 반드시 "계산값"으로 표시하라.
5. OCR 결과와 이미지 판독이 다르면 이미지 판독을 따르고, 차이를 명시하라.
6. 찾지 못한 것은 [미확인]으로 남겨라. 추정으로 빈칸을 채우지 마라.
7. 주제·제목·목차를 새로 제안하지 마라. 지시된 과제만 수행하라.
```

## 4. Claude 검증 게이트

Gemini 산출물 수령 시 아래 7항목을 점검한다. **지금까지 실제로 발생한 오류 유형에서 도출했다.**

| # | 점검 | 실제 발생 사례 |
|---|---|---|
| 1 | **수치 검산** — 합계·비율이 원문과 맞는가 | 총계 884억(→879), 45.2:54.8(→75:25) |
| 2 | **근거 실재** — 인용한 파일·목록이 실제로 있는가 | "신문 기사 목록", "선행연구 서술" 근거가 부재 |
| 3 | **쪽수 유무** — 빈도·인용에 위치가 붙었는가 | "중복투자 4회", "국산화 6회" 쪽수 없음 |
| 4 | **원문 방향** — 서술이 원문과 반대가 아닌가 | 업무분담 ETRI/기업 역할 뒤바뀜 |
| 5 | **고유명사** — 기관·법령·인물명이 정확한가 | KETI ≠ 1985년 통합 당사자 |
| 6 | **날짜·사양** — 연월·수치가 원문과 일치하는가 | 착수 9월(→8월), 16M DRAM 목표(→4M) |
| 7 | **확신도 표시** — 미확인이 확인으로 승격되지 않았는가 | 조합 설립인가 "1986년 7월 전후" |

**게이트 실패 시:** 해당 항목만 재작업 지시. 전체 재실행하지 않는다.

## 6. 사이클

```
Claude 지시서 작성
   → Gemini 실행 (과제 1개, 종료조건 준수)
   → Claude 검증 게이트 7항목
       ├ 통과 → 파일 반영, 다음 과제
       └ 실패 → 해당 항목만 재지시
   → 연구자 승인 (주제·목차·본문에 영향 있는 건만)
```

**한 사이클에 과제 하나.** 여러 개를 묶으면 Gemini가 느려지고 정확도가 떨어진다 — 실측된 사실이다.
